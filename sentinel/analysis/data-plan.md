# 訓練資料規則

## 範圍與狀態

64 個候選操作，第一版 normal、sqli、xss。尚未產生正式訓練資料；先完成固定版本與正常流程核對，見 [實施計畫](api-extension/plan.md)。契約不是已標記流量資料。

## 單筆資料

每筆代表一個 HTTP request，保存 request_id、替代 session／操作批次 ID、平台與固定版本、契約 SHA、method、path、query、必要 headers、body、解析狀態及契約比對結果。另存人工標籤、情境依據與模板家族。

response status 與非敏感業務結果只作核對及資料品質檢查，不作推論特徵。密碼、Token、Cookie、Authorization、API key 實值不進模型或一般資料集；實際請求值與 schema 的同名欄位結構分開處理。

## 收集內容

- 正常商品查詢、顧客、地址、購物車、配送、付款設定與訂單完整流程。
- 正常引號、標點、網址、中英文、技術文字及合法標記。
- 非攻擊錯誤，例如缺欄位、格式錯誤、過期憑證或不存在的商品。
- 經人工審核且位於合理欄位的 SQLi／XSS 嘗試，不把 HTTP 錯誤碼當作標籤。

流程支援端點的正常流量也要納入誤報檢查。按共同業務事件控制平台與類別分布，列出各端點／事件／類別樣本數；不要求每個 API 都有每種攻擊，不用不存在的功能湊類別。

## 分組與對帳

同一 session／操作批次、模板家族及近似變體不可跨訓練與測試，共用模板家族也須跨平台隔離。先分組，再擬合前處理與詞彙表。平台名稱、情境名稱、標籤與 response 不作推論特徵。

測試端獨立保存送出與收到的結果，用 request_id 與伺服器對帳。Medusa 前置驗證拒絕的請求可能不進目前 logger；未出現在日誌不能當成已被模型防禦。先以少量人工檢查資料確認流程、解析與標籤，再擴充資料。
