# 特徵方法分析

第一版標籤為 normal、sqli、xss，範圍見 [API 與分類規則](api-scope.md)。尚未實作正式特徵擷取與模型訓練。

## 共用流程

HTTP request → 分別解析 method、path、query、Content-Type、body → 計算數值／文字特徵及必要的契約比對資訊 → 固定欄位順序的向量 → XGBoost 三分類。

各部分分開取特徵後合併欄位，不把它們重新串成一段文字。平台特定 ID 與動態路徑需依契約辨識，避免只記住某個平台的 URL。原始值與受限解碼後的特徵分開保留。

## 比較方法

| 方法 | 特徵 | 目的 |
|---|---|---|
| A | 完整請求文字的 TF-IDF 加數值特徵 | 作為基準方法 |
| B | method、path、query、Content-Type、body 分開取特徵 | 評估結構化解析 |
| C | B 加上 OpenAPI 契約資訊 | 評估契約輔助是否降低正常流量誤報 |

解析失敗、找不到契約、本文大小與解析深度／處理時間超限須明確表示。沒有找到契約不等於攻擊。密碼與憑證實值、平台名稱、情境名稱、標籤及 response 結果不作推論特徵。

TF-IDF 詞彙表、前處理與選特徵只用訓練資料擬合；分組與評估見 [驗證計畫](validation-plan.md)。
